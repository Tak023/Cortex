Part one

Summary

What the review got right, what it got wrong, the larger problem underneath, and where it ended.

The review's three P0s shared a single root cause: Cortex displayed state it did not govern. Each agent CLI decided its own authentication, working directory and approval posture, and the interface rendered whatever those defaults happened to be — next to seeded registry metrics drawn in the same style as measured ones. The fix was one module that makes those decisions explicitly, plus provenance on every number shown.

The finding underneath the findings

Finding 06 argued that every task was routed to the expensive lane. The conclusion was right; the mechanism was not. Ten of thirteen agents had no live adapter at all. The pipeline never called Claude, Codex or Grok — it simulated them under their names.

Following that thread led to the real gap: the Implementation phase did not write software — it emitted a fixed starter page interpolating four concept fields, and no assets at any point. And fixing that exposed the deepest defect of all: even a perfect generation was destroyed thirty seconds later, because the Testing phase overwrote the app with the placeholder, generated tests asserting the placeholder's structure, passed them, and reported success. Five defects stacked, each hiding the next; none visible in a screenshot; every one found by running real projects and refusing to accept the green pipeline as proof.

Where it ended

Two applications now exist that Cortex built end to end on this machine, verified by loading them and reading the result, not by trusting phase status: Ember & Grind (55 files — branded roastery site with logo, favicon, shop with origin/roast/tasting-note data, per-bean detail pages, brew guides with a ratio calculator) and an OpenTheory community forum (84 files — dynamic routes, component library, data layer, its own e2e tests). Six phases green, and — for the first time — the green meaning what it says.

Part two

The ten review findings

For each: what the review observed, what was actually wrong in the code, what changed, and what was left.

P0 · COST01 — Claude auth falling through to metered API billingResolved
Observed

Terminal warned that both a claude.ai session and ANTHROPIC_API_KEY were set; header read "API Usage Billing" while the plan showed 0% of its window used. $160.53 Claude spend against $0.37 on Grok.

Confirmed

Exactly as described. ~/.claude/.credentials.json present and ANTHROPIC_API_KEY exported from ~/.zshrc line 4. The environment variable wins, so every token was metered while the subscription sat idle.

Fixed

New governance.ts detects both credentials and removes ANTHROPIC_API_KEY and ANTHROPIC_AUTH_TOKEN from the spawned process. A billing chip in the terminal header and fleet health strip makes the active mode visible; claudeAuthPreference allows metered billing to be chosen deliberately.

Closed at the source: ~/.zshrc:4 commented out with an explanatory note and backup. When metered use later became deliberate (Claude concept generation), the key went into Cortex's own env files rather than back into the shell — the same policy, applied in both directions. The headless coding adapter runs its children through the same governance, so it cannot reintroduce the leak.

P0 · SAFETY02 — Every agent rooted at the home directoryResolved
Observed

Four persistent agent processes, each with the entire home folder in scope, combined with broad fs/shell grants and Grok in always-approve.

Confirmed

resolveAgentCommand() hardcoded cwd = process.env.HOME for every agent, in both the web and desktop spawn paths.

Fixed

Workspace scope is a setting — active project, fixed directory, or home — defaulting to the most recent project workspace, falling back to home with a visible warning. The resolved directory shows as a chip in the terminal header, amber when home-scoped. The later code-generation work extended this: an agent writing files is confined to the project workspace by an assertion in the adapter itself, realpath-resolved so symlinks cannot escape it.

P0 · SAFETY03 — Approval policy inherited, not governedWhere verifiable
Observed

Claude Code in manual mode, Grok in always-approve. Nobody chose that asymmetry; it was each CLI's default.

Fixed

One fleet policy — inherit, read-only, ask, auto — translated into each CLI's own flags, passed only when the installed binary advertises both the flag and the value in its own --help. That safeguard earned its place immediately: this build of Claude Code accepts --permission-mode manual but has no default value, so the intuitive mapping would have aborted every governed launch. A read-only policy also disables code generation outright rather than being quietly ignored.

Limit

Enforced for Claude Code and Codex. Grok, Hermes and Antigravity expose no verifiable approval flag, so they report "CLI default" rather than pretending to be governed.

P1 · CORRECTNESS04 — Config truth is split, and the display layer is already lyingPartial
Observed

The roster showed grok-4.5 while the running process was Grok 4.6.

Fixed

A health endpoint probes --version live per CLI (cached five minutes); agent cards render it beside the configured model, which is dimmed and labelled as a preference rather than fact.

Limit

Version is live; the model is still declared, not read. No CLI exposes its selected model programmatically, so the stale string is contradicted by live data rather than eliminated.

P1 · TRUST05 — Real and simulated metrics are indistinguishableResolved
Confirmed

Worse than described. The registry seeded fabricated metrics for all thirteen agents — Claude at 412,000 tokens, 97% success — rendering identically to real data.

Fixed

Metrics carry provenance of seeded, simulated or measured, which only ratchets upward so a later simulated run cannot relabel real data as fake. Unmeasured values carry a chip and dotted underline, or hide entirely behind a setting. Fleet success rate averages measured agents only.

P1 · COST06 — There is no routing policy, only a registryResolved
Fixed

Nine task classes rather than pipeline phases, each with a stakes level that floors the required success rate. Cost is ordinal first — free-local < included-in-plan < metered; no hardcoded prices, real rates derive from local usage records. Only measured evidence promotes an agent — simulated runs are counted separately and never routed on. Budgets hard-stop metered spend; work degrades to local, and the project pauses with a reason if nothing free can run.

Live pipeline runs then hardened it: escalation after a failure originally walked the cost ladder — putting a coder-only local model on an architecture phase — and now walks a capability-filtered quality ladder instead (Part Three, 18).

P1 · UX07 — MCP denials are logged, not resolvedResolved
Fixed

Denials return a structured payload and surface as Grant once / Grant always / Deny, deduplicated per agent-server-tool. One-time grants live in memory with a ten-minute expiry, consumed on use — a one-time grant that survives a restart is not one.

Not done

Routing prompts to Discord, as the review suggested.

P1 · DATA08 — The vault index is stale and session capture is manualPartial
Fixed

The graph measures its own drift — notes on disk, notes indexed, notes modified since the build — and Graphify shows an explicit "index is behind" panel with a link to the always-current live layer.

Not done

Automatic re-extraction on change, and automatic capture of agent sessions on exit. Staleness is surfaced, not eliminated.

P2 · OPS09 — No fleet health view, and versions are driftingPartial
Fixed

A fleet health strip reads live from the machine: installed or not, binary path, reported version, auth mode, approval posture and workspace scope, with an amber banner counting metered and home-scoped agents. Nothing in it is seeded.

Not done

"Update available" detection, which needs per-vendor release checks.

P2 · HYGIENE10 — Smaller items worth a pass3 of 5
Fixed

Two token meters, one label — renamed to "Tokens · tracked by Cortex" and "Provider credits · billed by provider". Port sprawl — the health probe reports the endpoint that actually answered, flagging when it differs from the configured one. "8 MCP servers" versus 7 — the counter names its denominator and the SDK client card is badged "client · not a server".

Not done

PII in the interface — printed by Antigravity's own terminal output; rewriting it would break the passthrough design. Jarvis·Research at 10,898ms — not investigated.

Part three

Issues found in the product

Twenty-five defects the review could not have seen from screenshots. The ones that mattered most were found by running real projects — three successive live runs each exposed a layer the previous fix had been hiding.

The chain that blocked everything

Five defects stacked, each hiding the next: no adapters (the expensive agents were simulated) → no code generation (Implementation emitted a fixed placeholder) → work discarded on timeout (25 minutes of written files thrown away) → Testing reverted the app (overwrote it with the placeholder and passed tests written against that placeholder) → orphaned servers (a stale process serving the old build from memory, making a fixed app look broken and a broken verification look sound). A green pipeline survived all five.

#IssueWhat was wrong, and what changed
01Ten of thirteen agents were simulated Only the three Jarvis agents had a live adapter. Built an LM Studio adapter for the six on-device models and a headless adapter for Claude Code and Codex, using invocations verified against the installed binaries. Both pin their model and backend — an agent whose outcomes train a router must not silently substitute.
02Implementation never generated code A fixed template interpolating title, summary, features and stack — no feature code, no images, no icons, whatever was asked. A coding agent now implements the concept against the scaffold with write access confined to the project workspace, then verifies and repairs until it builds.
03Testing reverted the app it was testing The deepest one. generateAppTests(…, force: true) — which Testing always passes — bypassed the "only repair a broken stub" guard, overwrote app/page.tsx and layout.tsx with the placeholder, generated unit tests asserting the placeholder's "Features"/"Stack" headings, passed them, and reported "Build & real tests passed". A real implementation had no such headings, so even a flawless generation was reverted to make its own tests pass. Spotted because the reverted page carried an older footer string than the scaffold's — two divergent placeholder copies existed and Testing's won. Pinned by a test that fails with the exact page from the user's screenshot.
04Fallback documents described Cortex The "architecture" for a portfolio homepage announced an Agent Registry, a Router and an Orchestrator — the template named Cortex's own modules regardless of project. Rewritten to derive strictly from the concept and open with a banner stating no agent produced them.
05Escalation moved down, not up After Claude Code timed out on architecture, the retry went to a coder-only local model the capability filter says cannot do that class — the escalation path was the raw cost ladder, unfiltered and cheapest-first. Now capability-filtered and best-first: escalation is a quality decision, not a cost one.
06Timing out discarded 25 minutes of finished work Generation writes files as it goes, but the timeout path restored the snapshot wholesale — ~35 files that may well have built, thrown away. It now verifies whatever was written and restores only if that cannot be repaired.
07Timeouts sized for the wrong model Four minutes for an architecture document and twenty-five for generation — both exceeded by real runs on a reasoning model. Raised to 10 and 45 minutes. The same class recurred in the Claude concept-generation client: Grok's 90s bound would have timed out a measured 81s Opus run.
08Budget hard stop bypassed The curated-specialist fallback selected from the raw agent pool rather than the budget-filtered one, so a fully spent cap still routed to a paid agent — in two branches. A safety filter applied in one branch is not applied.
09Model ids never matched The registry stores lmstudio-community/Qwen3-Coder-30B-…-MLX-4bit; LM Studio serves qwen/qwen3-coder-30b. Neither is a substring of the other, so all five local agents would have failed and escalated to paid — making cost-aware routing worse than what it replaced. Replaced with token-subset matching on the bare name.
10Apps classified by topic, not stack "Static Dark Changelog for CLI Tools" (stack: Eleventy, Tailwind, GitHub Pages) was scaffolded as a command-line application, because the classifier ran includes("cli") over the title — which also fires on "client", "clipboard", "click" and "declining". Keywords now match on word boundaries and a named web framework or host outranks any topic keyword.
11Generated tests asserted text never promised The CLI suite required the concept title verbatim in help output; the implementation printed it lower-cased and three repair rounds tried to fix a mismatch that was never a defect. Same class as the web suite's placeholder assertions. Generated tests now describe behaviour the code is obliged to have, not strings it happens to emit.
12A passing build ≠ a usable app The first generation run compiled cleanly while referencing 105 class names with no CSS rule behind any of them — unstyled navigation, raw blue links. Added a style-completeness check; "compiles but unstyled" now feeds the repair loop as a first-class failure.
13Deleted projects left their dev servers running stopLaunchedApp existed and was never called from anywhere; the server registry was module-scoped, so any reload orphaned running servers permanently. A detached server then kept serving the deleted app's bundle from memory on the same port — a page indistinguishable from "the pipeline built nothing", misread as a pipeline failure twice. Delete now stops the server; a cwd-verified reaper handles servers this process did not start.
14Cortex's own instance orphans headless Next's standalone server rewrites process.title to "next-server", so the Electron main stops matching any pkill -f Cortex.app pattern. A partial kill leaves a headless main serving the old build — and because it still holds the single-instance lock, relaunching the app does nothing visible at all. Fixed with a pre-lock reap that distinguishes a stale orphan from a healthy instance by inode: after a reinstall the same path is a new directory. Live-tested through the full cycle: orphan reproduced, reaped on relaunch, healthy instance untouched, graceful quit leaves nothing.
15Path containment failed under symlinks macOS resolves /tmp to /private/tmp, so a lexical comparison silently skipped — a false negative that reads as "nothing to clean up", in the check that gates both killing processes and granting write access. One realpath-resolving helper now serves both, with symlink-escape cases tested.
16Claude has no default permission mode Accepted values are acceptEdits, auto, bypassPermissions, manual, dontAsk, plan. The obvious mapping would have aborted every launch; the help-probe caught it.
17Hermes was priced as free Typed local, so the cost model treated it as free on-device inference — but it bills a prepaid Nous Portal balance. An explicit billing signal now overrides process location.
18Lint reported 57,588 problems 99.9% from a vendored server and three build-output trees, git-ignored but unknown to ESLint. Real findings were buried. Baseline is now 20 warnings, zero errors.
19Fabricated token increment The scaffold step added 2,500 tokens to an agent's counter for an operation that spends none. Removed.
20Metrics double-counted Total tokens were agent counters plus half the usage records, annotated "rough"; latency and success averaged seeded placeholders. Rewritten to report by provenance.
21Cost used an invented rate Spend recorded as flat tokens × 0.000002 for every agent. Now priced against the agent's actual tier; simulated runs are no longer mislabelled as free-local inference.
22Stale-render bug in the terminal The "Save to Second Brain" button read a ref during render; ref writes do not re-render. Worked only because an unrelated state update happened to follow. Now driven by state.
23React Compiler deoptimisation A hook declared per-field dependencies while its body read the whole object, so the compiler skipped optimising it. Destructuring reconciles the two.
24LM Studio was not serving The application was running but its server was not listening, and the process ignored SIGTERM — which is why quitting appeared to do nothing. Enabled autostart; a cold start brings the server up in ~4s.
25Concept generation had one live provider Grok or canned templates, nothing between. Claude added as a second provider (structured outputs on claude-opus-5 — schema-constrained, no JSON scraping), with a shared prompt brief and every fallback carrying its accumulated reasons. Verified live both ways: 10 concepts in 81s with Grok unset; honest degradation to local with both keys unset.

Part four

Failures in this work

Seven mistakes made while fixing the above. Each produced a wrong conclusion that was stated confidently before being caught — most by testing against reality, two only because the user pushed back.

Pattern

Five of the seven are one error: a check contaminated by the thing it was checking. Fixtures invented rather than read from the live system; a process watcher matching its own command line; a shell inheriting the variable it was testing for; a port that answered standing in for the build behind it; a tool timeout read as task completion. Each looked like evidence and was not.

MistakeConsequence, and what was done
Test fixtures authored from imagination The model matcher passed nine hand-written cases and failed all five real model ids. Shipping it would have made every local agent fail and escalate to a paid one. Fixtures are now captured verbatim from the live backends and committed under tests/fixtures/.
Tests written to a temp directory "55 checks passing" was cited as verification for work with no durable tests; days later the harnesses had been cleaned up and nothing could be re-run. They now live in the repo behind npm test — and immediately caught an unrepresentative routing fixture. The report's own source made the same mistake and got the same fix.
Checks run inside the environment under test A pgrep watcher matched its own command line and reported its target alive indefinitely; a login shell spawned to verify an environment variable was gone inherited it from the parent and reported failure. Both stated as fact before correction; both needed isolation.
Verified an install against an orphaned old server After replacing the app, the settings endpoint answered with plausible values — from a headless process still serving the previous build out of memory. "Installed and verified" was reported twice on that basis. A port that responds is not the build behind it; process start time is now checked against install time before any conclusion.
Diagnosed a mechanism the evidence later contradicted The orphaned-server fix was committed with a "Next forks a worker" explanation. Live inspection showed no fork: the Electron main itself is retitled "next-server". The wrong model produced a quit handler that could never fire usefully; comments and handler were corrected, and the live test then found two further races in the corrected fix (a killed orphan's lock socket briefly accepting connections; a dying pid misread as a foreign process).
A tool timeout read as completion A 10-minute shell limit killed a codegen trial mid-run; because the build passed afterwards, "took over ten minutes" was reported as if the run had finished. The real measurement — a 25-minute live run — arrived later and contradicted the sizing built on the misreading.
A silent no-op driven as if it worked Pipeline approvals were scripted without the required taskId; the API returns 200 with the unchanged project, so the script polled a gate for over an hour believing it was clearing it. (The API's behaviour — accepting an approve that approves nothing — is listed as an open item below.)

The first two were caught by testing against reality — a live backend, a real pipeline run. The orphaned-server family was caught because the user twice refused to accept "it works" when the screen said otherwise. That pushback was correct both times.

Deliberately not done

  • PII masking — belongs to Antigravity's own output, not Cortex's to rewrite.
  • Jarvis·Research latency — the 10,898ms outlier was not investigated.
  • Vault auto-reindex and automatic session capture — staleness is surfaced; automation is not built.
  • Update-available detection — needs per-vendor release checks.
  • Twenty set-state-in-effect warnings — the fetch-on-mount pattern across every data panel; replacing it is a migration, not a cleanup. Kept visible as tracked debt.

Open, and worth closing

  • Approve without a taskId is a silent no-op. The action API returns 200 with the unchanged project. It should either error or approve the currently gated task. Cost one scripted run over an hour; a UI client never hits it, which is why it survived.
  • Implementation looks stalled while it works. The progress bar parks at 95% for the whole generation (15–30 minutes observed). It was reasonably read as a hang. Needs an elapsed-time indicator and expectation-setting copy.
  • Repair-loop convergence is thinly measured. Two products shipped clean; one run burned three repair rounds on a test assertion that was itself the defect. How reliably repair converges across concept types is not yet known.
  • LM Studio config persistence proven only against a hard kill — a graceful quit rewriting the autostart flag remains unproven, though evidence suggests it will not.
Five lessons worth keeping

Verify, don't guess, when shelling out to someone else's CLI. A wrong flag turns "not governed" into "will not start".

Never author test fixtures for an external system's output. Nine invented cases passed while all five real ones failed.

A test run inside the environment it tests will lie. Isolate it, or it reports on itself.

A green pipeline is not a working product. Six phases passed while Testing was overwriting the app with a placeholder and grading itself against it. The only check that found it was running the thing and reading the result.

A port that answers is not the build behind it. Twice, a replaced app was "verified" against a headless orphan serving the old code from memory. Identity checks (process start time, directory inode) are part of verification, not paranoia.
