Part one

Summary

What the review got right, what it got wrong, and the larger problem underneath.

The review's three P0s shared a single root cause: Cortex displayed state it did not govern. Each agent CLI decided its own authentication, working directory and approval posture, and the interface rendered whatever those defaults happened to be — next to seeded registry metrics drawn in the same style as measured ones. The fix was one module that makes those decisions explicitly, plus provenance on every number shown.

The finding underneath the findings

Finding 06 argued that every task was routed to the expensive lane. The conclusion was right; the mechanism was not. Ten of thirteen agents had no live adapter at all. The pipeline never called Claude, Codex or Grok — it simulated them under their names, so those token figures were registry seeds plus simulated accumulation rather than spend.

Following that thread led to the real gap, which no screenshot could show and which the review never claimed: the Implementation phase did not write software. It emitted a fixed starter page interpolating four fields from the concept — title, summary, feature list, stack — and no assets at any point. Whatever you asked for, you got the same page, under a heading that read "App scaffolded & build smoke passed".

That was found by running a real project through the pipeline, not by reading code. It is now fixed: a coding agent implements the concept against the scaffold, and the result is verified and repaired until it builds.

Part two

The ten review findings

For each: what the review observed, what was actually wrong in the code, what changed, and what was left.

P0 · COST01 — Claude auth falling through to metered API billingResolved
Observed

Terminal warned that both a claude.ai session and ANTHROPIC_API_KEY were set; header read "API Usage Billing" while the plan showed 0% of its window used. $160.53 Claude spend against $0.37 on Grok.

Confirmed

Exactly as described. ~/.claude/.credentials.json present and ANTHROPIC_API_KEY exported from ~/.zshrc line 4. The environment variable wins, so every token was metered while the subscription sat idle.

Fixed

New governance.ts detects both credentials and removes ANTHROPIC_API_KEY and ANTHROPIC_AUTH_TOKEN from the spawned process. A billing chip in the terminal header and fleet health strip makes the active mode visible; claudeAuthPreference allows metered billing to be chosen deliberately.

Closed at the source too: ~/.zshrc:4 commented out with an explanatory note and a timestamped backup, so sessions started outside Cortex also use the plan. The same policy is applied to the headless coding adapter added later, so it cannot reintroduce the leak.

P0 · SAFETY02 — Every agent rooted at the home directoryResolved
Observed

Four persistent agent processes, each with the entire home folder in scope, combined with broad fs/shell grants and Grok in always-approve.

Confirmed

resolveAgentCommand() hardcoded cwd = process.env.HOME for every agent, in both the web and desktop spawn paths.

Fixed

Workspace scope is a setting — active project, fixed directory, or home — defaulting to the most recent project workspace. Where no project exists it falls back to home with a visible warning. The resolved directory shows as a chip in the terminal header, amber when home-scoped.

P0 · SAFETY03 — Approval policy inherited, not governedWhere verifiable
Observed

Claude Code in manual mode, Grok in always-approve. Nobody chose that asymmetry; it was each CLI's default.

Fixed

One fleet policy — inherit, read-only, ask, auto — translated into each CLI's own flags. Flags are passed only when the installed binary advertises both the flag and the value in its own --help, probed and cached.

That safeguard earned its place immediately: this build of Claude Code accepts --permission-mode manual but has no default value, so the intuitive mapping would have aborted every governed launch.

Limit

Enforced for Claude Code and Codex. Grok, Hermes and Antigravity expose no verifiable approval flag, so they report "CLI default" rather than pretending to be governed.

P1 · CORRECTNESS04 — Config truth is split, and the display layer is already lyingPartial
Observed

The roster showed grok-4.5 while the running process was Grok 4.6.

Fixed

A health endpoint probes --version live per CLI (cached five minutes); agent cards render it beside the configured model, which is dimmed and labelled as a preference rather than fact.

Limit

Version is live; the model is still declared, not read. No CLI exposes its selected model programmatically, so the stale string is contradicted by live data rather than eliminated.

P1 · TRUST05 — Real and simulated metrics are indistinguishableResolved
Observed

A "Simulation tick: 1800ms" setting alongside Antigravity reporting 0 tokens with 1,300ms latency and 94% success.

Confirmed

Worse than described. The registry seeded fabricated metrics for all thirteen agents — Claude at 412,000 tokens, 97% success — rendering identically to real data.

Fixed

Metrics carry provenance of seeded, simulated or measured, which only ratchets upward so a later simulated run cannot relabel real data as fake. Unmeasured values carry a chip and dotted underline, or hide entirely behind a setting. Fleet success rate averages measured agents only.

P1 · COST06 — There is no routing policy, only a registryResolved
Observed

Six capable local models idle at single-digit thousands of tokens while Claude carried 449.4k and Grok 548.4k.

Fixed

Nine task classes rather than pipeline phases, since "implementation" covers both writing code and scaffolding tests. Each carries a stakes level that floors the required success rate independently of the user's setting.

Cost is ordinal first — free-local < included-in-plan < metered. No hardcoded prices: Cortex cannot know which model a passthrough CLI selected, so a price table would be a guess. Real rates derive from local usage records after five samples.

Only measured evidence promotes an agent. Outcomes are tracked per agent and class; simulated runs are counted separately and never routed on. Failures exclude that agent from the retry, so escalation walks up the cost ladder.

Budgets hard-stop metered spend per day and per project; work degrades to local, and the project pauses with a reason if nothing free can run.

The prerequisite was making local models run at all — see Part Three, issue 01.

P1 · UX07 — MCP denials are logged, not resolvedResolved
Observed

A denial appeared three times in the activity feed. The ACL worked as designed; the failure was that a decision point rendered as a dead-end error.

Fixed

Denials return a structured payload and surface as Grant once / Grant always / Deny, deduplicated per agent-server-tool. One-time grants live in memory with a ten-minute expiry, consumed on use — a one-time grant that survives a restart is not one.

Not done

Routing prompts to Discord, as the review suggested.

P1 · DATA08 — The vault index is stale and session capture is manualPartial
Fixed

The graph measures its own drift — notes on disk, notes indexed, notes modified since the build — and Graphify shows an explicit "index is behind" panel with a link to the always-current live layer.

Not done

Automatic re-extraction on change, and automatic capture of agent sessions on exit. Staleness is surfaced, not eliminated.

P2 · OPS09 — No fleet health view, and versions are driftingPartial
Fixed

A fleet health strip reads live from the machine: installed or not, binary path, reported version, auth mode, approval posture and workspace scope, with an amber banner counting metered and home-scoped agents. Nothing in it is seeded.

Not done

"Update available" detection, which needs per-vendor release checks.

P2 · HYGIENE10 — Smaller items worth a pass3 of 5
Fixed

Two token meters, one label. Renamed to "Tokens · tracked by Cortex" and "Provider credits · billed by provider". They measure different things and should never have shared a label.

Port sprawl. The health probe reports the endpoint that actually answered, and Settings flags when it differs from the configured one — so a fallback reads as a fallback.

"8 MCP servers" versus 7. The counter names its denominator and the SDK client card is badged "client · not a server", which is what made eight cards read as eight servers.

Not done

PII in the interface — printed by Antigravity's own terminal output; rewriting it would break the passthrough design. Jarvis·Research at 10,898ms — not investigated.

Part three

Issues found in the product

Seventeen defects the review could not have seen from screenshots — including two in code written to fix the review itself.

The three that mattered most

The Implementation phase did not write software. It scaffolded a fixed page from four concept fields and generated no assets ever. A live run asking for branding and a favicon produced neither, under a message reading "App scaffolded & build smoke passed".

The budget hard stop was a suggestion. In the new router, the "no cheap agent qualified" fallback selected from the raw agent pool instead of the budget-filtered one, so a fully spent cap still routed to a paid agent.

Model matching failed on every real model. The registry stores lmstudio-community/Qwen3-Coder-30B-…-MLX-4bit; LM Studio serves qwen/qwen3-coder-30b. Neither is a substring of the other, so all five local agents would have failed and escalated to paid — making cost-aware routing worse than what it replaced.

#IssueWhat was wrong, and what changed
01Ten of thirteen agents were simulated Only the three Jarvis agents had a live adapter. Built an LM Studio adapter for the six on-device models and a headless adapter for Claude Code and Codex, using invocations verified against the installed binaries. Both pin their model and backend: chat may substitute another loaded model, but an agent whose outcomes train a router must not.
02Implementation never generated code A fixed template interpolating title, summary, features and stack — no feature code, no images, no icons, whatever was asked. A coding agent now implements the concept against the scaffold with write access confined to the project workspace, then verifies and repairs.
03Fallback documents described Cortex The "architecture" for a portfolio homepage announced an Agent Registry, a Router and an Orchestrator, because the template named Cortex's own modules regardless of project. Rewritten to derive strictly from the concept and to open with a banner stating no agent produced them.
04Budget hard stop bypassed Curated fallback ignored the budget filter in two branches. Both now select only from agents that survived it. A safety filter applied in one branch is not applied.
05Model ids never matched Substring matching cannot bridge publisher prefixes. Replaced with token-subset matching on the bare name, which tolerates dropped qualifiers while still refusing genuinely different models.
06A passing build ≠ a usable app The first generation run compiled cleanly while referencing 105 class names with no CSS rule behind any of them, rendering unstyled navigation and raw blue links. Added a style-completeness check; the repair loop now treats "compiles but unstyled" as a failure alongside compile errors.
07Claude has no default permission mode Accepted values are acceptEdits, auto, bypassPermissions, manual, dontAsk, plan. The obvious mapping would have aborted every launch; the help-probe caught it and the mapping uses manual.
08Hermes was priced as free Typed local, so the cost model treated it as free on-device inference — but it bills a prepaid Nous Portal balance. An explicit billing signal now overrides process location; only genuine on-device inference counts as free.
09Lint reported 57,588 problems 99.9% came from a vendored server and three build-output trees, all git-ignored but unknown to ESLint. Real findings were buried, which is why two trivial errors had sat unnoticed. Baseline is now 20 warnings, zero errors.
10Fabricated token increment The scaffold step added 2,500 tokens to an agent's counter for an operation that spends none. Removed.
11Metrics double-counted Total tokens were agent counters plus half the usage records, annotated "rough"; latency and success averaged seeded placeholders into fleet-wide figures. Rewritten to report by provenance.
12Cost used an invented rate Spend was recorded as a flat tokens × 0.000002 for every agent. Now priced against the agent's actual tier, so local and plan-covered work correctly costs nothing.
13Simulated runs tiered as free-local Template synthesis was attributed to on-device inference in the usage ledger. Now recorded as simulated.
14Stale-render bug in the terminal The "Save to Second Brain" button read a ref during render; ref writes do not re-render. It worked only because an unrelated state update happened to follow. Now driven by state.
15React Compiler deoptimisation A hook declared per-field dependencies while its body read the whole object, so the compiler skipped optimising it. Destructuring reconciles the two; the manual dependencies were correct.
16Two inert eslint-disable directives For rules not enabled anywhere. Replaced with the reasons they existed, rather than deleting the intent along with the directive.
17LM Studio was not serving The application was running but its server was not listening, and the process ignored SIGTERM — which is why quitting appeared to do nothing. Enabled autostart in its config; a cold start now brings the server up in about four seconds.

Part four

Failures in this work

Four mistakes made while fixing the above. They are listed because each produced a wrong conclusion that was stated confidently before being caught.

Pattern

Three of the four are the same error: a check that was contaminated by the thing it was checking. Fixtures invented rather than read from the live system; a process watcher that matched its own command line; a shell spawned to confirm an environment variable was gone that inherited it from its parent. Each looked like evidence and was not.

MistakeConsequence, and what was done
Test fixtures authored from imagination The model matcher passed nine hand-written cases and failed all five real model ids. Shipping it would have made every local agent fail and escalate to a paid one. Fixtures are now captured verbatim from the live backends and committed under tests/fixtures/.
Tests written to a temp directory "55 checks passing" was cited as verification for work that had no durable tests; four days later the harnesses had been cleaned up and nothing could be re-run. They now live in the repo behind npm test — and immediately caught an unrepresentative routing fixture of my own.
Checks run inside the environment under test A pgrep watcher matched its own command line and reported its target alive indefinitely; a login shell spawned to verify an environment variable had been removed inherited it from the parent and reported failure. Both were stated as fact before being corrected. Both needed isolation.
Diagnosed source without checking the build The desktop app in use was four days older than the source being discussed, so two fixes were explained as present when they had never been packaged. Build provenance is now checked against commit timestamps before drawing conclusions from observed behaviour.

The first two of these were caught only because the work was tested against reality — a live backend, and a real pipeline run. The third and fourth were caught because a claim was challenged.

Deliberately not done

  • PII masking — belongs to Antigravity's own output, not Cortex's to rewrite.
  • Jarvis·Research latency — the 10,898ms outlier was not investigated.
  • Vault auto-reindex and automatic session capture — staleness is surfaced; automation is not built.
  • Update-available detection — needs per-vendor release checks.
  • Twenty set-state-in-effect warnings — the fetch-on-mount pattern across every data panel. Replacing it means adopting a data-fetching library or server components: a migration, not a cleanup. Kept visible as tracked debt.

Open, and worth closing

  • Code generation has not run inside the packaged app. It is verified by driving the same invocation against a copy of a real workspace, and by unit tests, but the first pipeline run through the rebuilt desktop app will be its first end-to-end exercise.
  • Generation quality is a single data point. One concept produced a clean build and the requested assets on the first attempt, but with an unstyled result that the new check would now catch and repair. How reliably the repair loop converges is unmeasured.
  • Configuration persistence is proven only against a hard kill. The LM Studio autostart setting survived SIGKILL and a cold start; a graceful quit rewriting the file remains unproven, though evidence suggests it will not.
Four lessons worth keeping

Verify, don't guess, when shelling out to someone else's CLI. A wrong flag is worse than no flag: it turns "not governed" into "will not start".

Never author test fixtures for an external system's output. Read them off the live system. Nine invented cases passed while all five real ones failed.

A test run inside the environment it tests will lie. Isolate it, or it reports on itself.

A green pipeline is not a working product. Six phases passed, the build compiled, and the app was a placeholder. The only check that found it was running the thing and looking at the result.
